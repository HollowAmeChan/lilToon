# Ho lilToon 照明重构计划

2026-11-03。根据 [照明参数审计](liltoon-lighting-controls-audit.md) 和用户决定制定；本文件是待实施方案，不表示 Shader 已改完。范围是材质直接受光、Cast 消费与对应编辑入口；独立预设窗口的大修另外推进。

## 前置：Shader 裁剪基线已建立

2026-11-03，裁剪对话 `01a19e1e-b2d0-7212-8d6e-753d0117f402` 中的 Multi、OnePass、Overlay、OutlineOnly 等退出路径已在当前 `master` 提交。照明改动只针对仍保留的不透明、Cutout、透明及其描边、TwoPass、OIT 路径；不恢复已删除资源，也不为退出的 Hair / Fur / Refraction 分支加兼容逻辑。TwoPass Transparent 与保留表面模式的正常描边仍属于支持范围。

**2026-11-03 主工程复核进展：** Full 的 realtime HoShadowCast 接收已改为 URP 附加灯 buffer 索引逐灯映射。主 Toon 阴影只消费显式 `includeInMainShadow` 来源；Full 对匹配到的附加灯使用该灯的 Ho 可见度，图集未收录或投影不覆盖时回退 URP 原生可见度，不将整个 ShadowCast 灯池乘进主光或整份材质。Ho 可见度命中时替代同源 native 衰减，避免重复采样。固定映射数组在 C# / HLSL 维持一致长度。

BREAK_URP 主工程（Unity 6000.3.15f1、URP 17.3 Forward+、D3D12）中对万象天文与冷色古堂各运行了 960×540、48 帧 Main/Full、0/1/2 倍率探针。修复后 Main 与 Full/1x 平均亮度分别为 28.862 / 28.874 与 16.195 / 16.186；修复前万象天文 Full/1x 为 26.147。两个场景的 `.unity` 与 `.mat` 文件哈希均保持基线值。BREAK_URP 这 27 个舞台的旧材质仍显式为 Main=1，未批量迁移；新建舞台继续以 Main=1 作保守默认。

**未完成的验证边界：** 以上场景灯均为 Realtime。Mixed / Lightmap Shadowmask / APV 的 `InputData.shadowMask` 传递、Lightmap 与 APV 路径仍需独立验证；不得把 realtime 场景结果外推到这些模式。附加灯身份映射超出固定 256 项时按 URP native fallback 处理。

## 目标与已确定的取舍

- 删除重复的 Ho HDR 增亮分支，统一保留 HDR 光色精度。
- 一盏附加灯只在对应的受光路径中计入一次；颜色、着色方向、阴影可见度分别计算。
- 多光源受光强度拥有明确的 0 / 1 语义；附加光阴影接收强度真正生效。
- 取消“合成方向偏离主光就自动放开 Cast”的公式，保护精细角色投影和斑驳阴影。
- 删除顶点灯强度、曝光前最大亮度、旧 HDRP 定向光强度、Built-in ForwardAdd 透明度提升 / 光照混合等无效功能。
- 移除照明页的默认 / 半单色预设按钮及其独立套用逻辑；材质批量修改仍只修改用户动过的属性。
- 推荐移除 Unlit 化，不将它改名复用为环境光强度。
- 原始生产场景是用户当前作品，迁移按明确选择执行；不重跑历史配方，不添加每次全场景严格审查。

## Unlit 化为何不等于环境光强度

原版公式是 `受光色 = lerp(受光色, 白色1, AsUnlit)`：数值越大，材质基础色越少随场景光照变化。典型用途是让贴图 / 二次元底色在黑暗或彩色光环境里保持较固定的可见性。这是从公式可以确认的效果，不推测作者唯一的创作动机。

真正的环境光强度应缩放 SH / Probe / APV 等间接贡献，保留主光、附加灯的直接受光；它不会在完全没有环境光时凭空插入白色。因此不能把 `_AsUnlit` 换个标签就称为环境强度。

当前工作流依靠灯光、Toon 阴影和 HoGI 塑形，建议移除这个通用混合旋钮。确有固定底色的特效需求时，使用有明确受光模式的专用材质。环境受光强度若未来需要，应连同 RTGI 的接收数据一起单独设计，本轮不以旧 Unlit 字段代替。

一次只读 `.mat` 扫描得到：1,335 个可读文件，1,229 个显式保存 `_AsUnlit`，全部为 0；1,209 个保存旧多光源强度，其中 918 个非零；1,208 个保存旧多光源 Cast 强度，其中 892 个非零。这是序列化文本统计，尚不覆盖 Prefab 内嵌材质、Variant 继承、动画和 MPB 的最终有效值，也不把每个文件都断言为当前 Shader。

## 新材质参数契约

| 参数 | 建议行为 |
| --- | --- |
| 亮度下限 | 保留。约束未遮挡照明的基础保底；不能在 Cast / AO 之后对最终颜色 `max`，把遮挡再抬亮。 |
| 亮度上限 | 保留。统一限制材质 diffuse 照明域，Ho 附加灯也必须纳入；允许 HDR 上限。不能夹整个最终像素，以免伤害自发光、环境反射或后处理。 |
| 单色照明 | 保留。对主光和附加灯的 diffuse 受光使用同一规则；材质贴图本色、发光不随之灰度化。 |
| 阴影颜色的环境影响 | 保留其 Toon 暗侧填充的艺术用途，并保持依赖环境输入；不伪装成整个 GI 的强度。 |
| 多光源强度 | 新语义是材质对实时附加灯直接受光的统一倍率。0 为不贡献，1 为正常一次，超过 1 为明确的艺术增强。主光、环境 / GI 不随它关闭；已烘进 Lightmap 的光不能靠实时倍率撤回。 |
| 附加光阴影接收 | 重新接入旧“多光源阴影强度”的功能。0 忽略相应附加来源的 Cast，1 正常接收；不改变灯光 RGB、范围、强度，不关闭其他物体的投影计算。 |
| HoRP阴影模式 | 保留 Main / Full。控制 Cast 来源范围，不用于选择接收哪些灯的颜色。 |
| 光照方向覆盖 / 跟随对象 | 保留为 Toon 的艺术方向偏置，明确不旋转真实投影；不再自动减弱 Cast。 |

基础保底和限幅要在光照域完成，保持光源归属；不能先乘逐灯可见度，再用下限给被完全遮挡的那盏灯“补回来”。实现时用数值用例锁定处理顺序。

“多光源强度”还要核对保留路径中依赖 `fd.lightColor` / `fd.L` 的高光、背光、SSS 等直接受光消费者。不能只有 diffuse 关掉，而该灯的其他直接贡献仍从合成数据里漏进来。环境 Cubemap / PLR 反射、自发光和屏幕 RTGI 保留各自契约；已退出的独立 Hair / Fur 家族不再改造。

## 单次采光与方向职责

现状需要删除的是 `lilGetAdditionalLightHDR` / `LIL_APPLY_ADDITIONAL_LIGHT_HDR` 的第二次补加与其整池压暗。裁剪后只处理仍然存在的公共实现和调用点，不为已删除的 Hair / Fur Pass 做修复。

新的实现按 URP 的点聚光 Cluster 列表和附加方向光列表分别遍历各自候选，不再重复遍历同一批灯做“基础 + 额外 HDR”：

1. 获取正确光源颜色、Cookie、距离 / 锥角衰减和 Lighting Layers。
2. 应用材质的附加光倍率，保留浮点 HDR，不提前 `saturate`。
3. 按模式取得该光源可见度，仅在它自己的直接贡献上使用普通 Full 遮挡。
4. 累加需要的光色 / 局部受光数据；高光等需要真实方向的消费者保留该灯方向，不伪装成一个全局合成方向。
5. 主 / 环境 / 附加 diffuse 使用一致的艺术校正规则，再完成 Toon、Cast、AO 及其余材质流程。

默认有主光时，以主光和艺术覆盖确定主 Toon 明暗方向，附加灯提供颜色、距离 / 锥角范围和自身局部受光，不自动改写主方向。没有主光时采用稳定的环境后备，并防止零向量归一化。

需要“补光也带动主 Toon 方向”的创作模式时，未来可以做明确的高级入口；本轮不默认新增一堆方向权重旋钮。即使允许改方向，也不恢复任何“方向变了就消除 Cast”的隐式逻辑。

## Main / Full 与逐灯阴影

两个消费口分工：

- **Main** 是主光 / 角色精细投影与用户显式指定的艺术投影通道。基础主光继续按已有有效性条件选择 RTShadow、CharacterShadow、URP 主光后备；不能从颜色合成方向推导或削弱其可见度。
- **Full 的普通附加部分** 是按灯归属的可见度：该灯被挡，只削减该灯贡献。禁止把所有灯最暗的值或可见度乘积直接乘到整份材质颜色上。

显式“加入主阴影”的附加灯属于用户选择的艺术例外，允许投影影响公共 Toon 阴影层。它已经在 Main 被消费，Full 不能再对同一来源重复采样并叠一遍。普通灯不能因为被某个 Feature 自动收集，就隐式升级成全局压暗来源。

材质“附加光阴影接收”按附加来源应用，显式加入 Main 的附加灯也遵循它；主灯本身不随此倍率变化。各 Toon 层原有的 ShadowReceive 和接收遮罩仍控制该层是否接收相应 Cast，避免再造平行的主光强度入口。

逐灯接收使用 `lerp(1, visibility, receiveStrength)`。提供者已经消费过的 `Light.shadowStrength` 不能再乘一次。每个来源必须标明由哪一个提供者解析，不能同时把 native / Ho / RT 的同源遮挡叠乘。

生产端要求：

- 尊重 Light 启用状态、None / Hard / Soft、Realtime / Mixed / Baked、Lighting / Shadow Rendering Layers 和 Culling Mask。
- URP 后备走带正确 ShadowMask 的采样；不能把 `InputData=(InputData)0` 当作 Lightmap / APV 遮罩。
- 保留 URP 已有的实时 / 烘焙可见度混合。Lightmap、传统 Probe、APV 不等价，也不能用 APV 代替一盏动态灯的精细 Cast。
- HoShadowCast 当前图集按自有紧凑槽位排列，需要把该槽位和 URP 灯光身份对应，不能直接拿相同数组下标互相采样。处理未进图集和预算不足的后备。
- 本轮保留 HoShadowCast 生产者作为显式艺术 / 指定灯高质量图集来源；取消其普通灯“整池压黑整个材质”的消费方式。是否退役 Feature 仍需实际后备效果与性能证据。
- 未来附加 RT 阴影复用同一个逐灯 / 分组光照契约；不要预设一张灰度 FullMask 可以准确代表任意颜色、任意数量的灯。材质端沿用可控候选列表，不遍历全场景的“无限灯”。

## 取消方向差补偿

`lil_common_frag.hlsl` 的 Toon 阴影、背光、SSS 目前都存在 `saturate(attenuation + distance(L, origL))`。统一改为取得对应通道实际可见度，保留各功能自己的接收开关 / 遮罩。

主 Toon 的明暗方向可变，Cast 的位置和可见度由真实灯光 / 提供者决定，二者彼此不覆盖。真实补光仍可能照亮暗面，那是光色贡献；不能再通过把遮挡数值抬成 1 达到“照亮”效果。

## 迁移与分步提交

不能把现有两项旧数值直接解释成新契约：

- 旧多光源强度 0 仍有基础附加光，新语义 0 必须关掉该实时直接贡献；新材质中性值应为 1。
- 旧多光源 Cast 数值没有效果，新接入后一大批已保存的非零值会真的产生遮挡。
- `1 + 旧HDR增益` 只能粗略近似部分未限幅情况，不能作为保证外观等价的全量自动换算。

做一次范围明确的材质迁移入口，记录版本并报告受影响项；读取实际保存属性，不能靠改 Shader 默认值假装已经迁移。先核对 Unlit 的 Variant / MPB / 动画引用，然后清理；无需引入永久的双渲染后端。运行时不用展开两套完整采样图来“兼容”旧材质。

前置完成条件：裁剪对话完成本轮约定范围、提交变更并取得保留路径的编译基线。届时先核对实际保留的模板 / Pass / 输入，删除本计划中已被对方解决的工作，再分步交付：

1. **稳定 Cast 接收**：取消方向差补偿，统一 Toon / 背光 / SSS 的接收解析，加入方向变化不改变原始可见度的测试。
2. **统一附加光与 Full 归属**：单次采光、倍率、逐灯 native / Ho 后备与身份映射一起落地；不先做一个继续整体压暗的临时补丁。
3. **收敛参数与界面**：颜色控制覆盖统一 diffuse 域，移除 Unlit / 兼容死项 / 旧预设按钮，更新材质管理器、生成器和初始制作工具。
4. **一次迁移与实际复核**：选一份角色测试和一个现有舞台，有限机位 / 关键帧比较，记录必要的人工亮度修正，更新文档与经验入口。

正在发生的其他仓库清理不混入本计划提交；实现前应以当时已落地的代码为起点，避免覆盖用户或其他任务的修改。

## 验证重点

- 同一盏灯只贡献一次，附加倍率 0 / 1 / 2 语义正确；主光与环境不随附加倍率关闭。
- A 红灯被挡、B 蓝灯可见：A 的遮挡不能压暗 B；换颜色仍成立。
- None、零投影强度、Baked、Mixed、Layer、Light Cookie、ShadowMask / Probe / APV 输入和预算后备逐项验证。
- Main 忽略普通附加 Cast，Full 正常接收；显式 Main 来源只处理一次，材质接收倍率不改灯光颜色。
- 30° / 60° 艺术方向变化不再把实际 Cast 抬亮；实际有补光时允许颜色明暗自然变化。
- 单色覆盖附加 diffuse；上下限不放过额外补加，也不夹坏自发光 / 反射；下限不能让被挡灯重新发光。
- 保留的不透明 / Cutout / 透明 / 描边 / TwoPass / OIT 路径与 SSS / 背光接收遵循同一契约。检查直接高光的方向归属；不为已删除家族保留测试依赖。
- 检查 HLSL 字节码 / 编译耗时与一个固定负载的 GPU 时间，不引入双分支完整 PCSS 展开或大量材质 Keyword。
- 既有 14 项现状审计中证明缺陷的断言要改成新契约预期，不能继续把缺陷复现当作“正确性通过”。

验证只围绕本轮改动，不批量重置制作场景，不重渲全部视频，不要求固定历史截图一模一样。
